## 0. Prinsip (berlaku di semua peran)
0. **Dashboard = layanan kritikal run (ATURAN PERTAMA).** Setiap run punya alamat dashboard sendiri `http://127.0.0.1:4173/?run=<RUN>#manager` (run yang bukan run aktif tampil hanya-baca dengan statusnya; sebelum RUN dialokasikan pakai `/#manager`). Dashboard `127.0.0.1:4173` wajib hidup sejak frase trigger dikenali (sebelum RUN dialokasikan) sampai FASE 8 selesai; target desain **nol downtime**. Manager memilikinya dan tiap turn WAJIB cek listener dengan `netstat -ano | findstr :4173` (jangan `curl` dari proses anak agen — LPAC memblokir HTTP anak). Bila mati: **fail-closed** — tidak ada email, undangan, keputusan outbox, rilis bukti, penerbitan laporan, maupun pembuatan/ubah/hapus task sampai dashboard pulih; catat `dashboard_down`, pulihkan, lalu lanjut dari state. Server dijalankan dari **terminal eksternal atau watchdog residen**, bukan child process agen, dan tidak pernah di-bind ke `0.0.0.0`; hanya satu instance. Server yang sehat TIDAK boleh di-kill atau di-restart "untuk jaga-jaga" — restart hanya oleh watchdog saat health check gagal. Bila panel preview Manager tertutup, buka kembali `http://127.0.0.1:4173/?run=<RUN>#manager` (IPv4 eksplisit: `localhost` bisa jatuh ke IPv6 `::1` dan gagal) tanpa menyalakan server kedua. **Batas kejujuran:** target nol downtime bukan jaminan platform — crash proses, sleep/restart PC, dan bind ulang port tetap memberi jeda pemulihan; watchdog + fail-closed mencegah aksi gelap saat jeda itu. Benar-benar 0 ms butuh instance redundan + proxy failover, di luar scope simulasi ini. **Trigger = start dashboard:** frase `mulai audit ISO 27001` (dan seluruh varian trigger di frontmatter) adalah JUGA perintah menyalakan dashboard. Langkah PERTAMA saat trigger dikenali — SEBELUM `run-counter.json` ditulis, sebelum alokasi RUN, sebelum audit log, outbox, task, email, atau rilis apa pun — jalankan `npm run ensure` di `progress-dashboard`: `DASHBOARD_UP` = reuse instance sehat, `DASHBOARD_STARTED` = watchdog residen menghidupkan port 4173, `DASHBOARD_DOWN` = **fail-closed** (jangan alokasikan RUN, tampilkan kartu kendala). Perintah ini tidak pernah mematikan server sehat dan tidak pernah membuat instance kedua; watchdog tetap menjaga sesudahnya.

## 5. Metode ISO/IEC 27001:2022 — conformity, tanpa skor
- Status per item: **Conform** · **Minor NC** · **Major NC** · **OFI** · **N/A**. Tidak ada skor angka, persentase, maturity level, atau severity LOW/MEDIUM/HIGH.
- **Major NC**: kontrol tidak ada/tidak diterapkan, atau klausul wajib 4–10 tanpa bukti, atau tujuan ISMS gagal. Satu Major NC = belum layak sertifikasi.
- **Minor NC**: kontrol ada tetapi penerapan tidak konsisten/tidak lengkap; atau kontrol Annex A tanpa bukti setelah klarifikasi dijawab "Belum tersedia". CAP ≤ 90 hari.
- **OFI**: tidak melanggar, ada peluang perbaikan (keputusan auditor, beri alasan).
- **N/A**: hanya dengan justifikasi pengecualian (klausul 6.1.3 d).
- Konflik sumber: sumber terbaru yang sah menang, KEDUA sumber disitasi, dokumen lama ditandai untuk diperbarui.
- SoA: kolom Kontrol · Judul · Penerapan (`Implemented` / `Not implemented` / `Excluded`) · Justifikasi · Dinilai siklus ini (ya/tidak).
- Setiap temuan: klausul/kontrol, status, bukti objektif (file + kutipan), uraian, tindakan korektif usulan, pemilik, target.
